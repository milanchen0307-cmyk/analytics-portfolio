# 内容决策实验室：方法与标注手册

## 研究问题与交付物
对有明确预算、口味和使用场景的用户，按评价对象、理由和情境整理信息，是否比整篇好评／差评更有决策价值？

已完成：真实案例整理、初步标注规则、可运行的约束检查原型、12个模拟场景及回归测试。尚待开展：独立标注一致性检验与真实参与者使用测试。

## 数据来源分层
真实材料为用户提供的4份中文截图，16个初步评价单元，来源A–D。单元不是独立用户。保留旧版annotations.json/CSV；不把模拟记录追加进去。

synthetic-cases.json中的S01–S12全部为AI辅助编写的测试夹具。餐厅不指向真实商家，金额、好评数、用户条件均为设定。每个场景包含原文、人工结构化字段、用户约束与规范定义的预期结果。它们覆盖失败类型，不用于推断总体分布。

## 标注字段与操作规范
| 字段 | 规则 | 例子 |
|---|---|---|
| 评价对象 | 尽可能拆到菜品/服务环节，不能只给整篇标签 | 汤、服务等待、室外海景 |
| 倾向 | 正面、负面、中性；未提及单独记缺失 | 只写价格不等于嫌贵 |
| 理由 | 保存能够支持判断的原文跨度 | “太咸”支持口味负面，不支持不新鲜 |
| 情境 | 时间、天气、座位、菜品不同不能直接视为事实矛盾 | 雾天看不到海不证明晴天也看不到 |
| 费用 | 金额、币种、整桌/人均、人数、税费状态分别记录 | 人数未知时不能把300美元整桌费用换算成人均 |
| 来源 | 原始编号及摘录；真实来源与模拟来源分开 | A/U01 与 synthetic/S01 |
| 分歧 | 偏好不同、体验条件不同、事实含义待核查 | “直视日落”与“看到余晖”不能合并 |

复核顺序：先检查是否同对象、同情境，再判断是态度差异还是事实分歧。不以点赞数推断可靠性，不以中文/英文推断作者国籍或口味。

## 约束策略
1. 用户明确选择的条件才作为硬约束；不替用户猜测。
2. 模拟场景中已设定的确定人均含税费用超出预算时，输出“不符合条件”，即使同时存在其他未知项。真实应用中必须先核验费用来源与时效。
   单条“对我太咸”等主观反馈只触发“需要补充信息”，不直接判定不适合另一个用户。
3. 无明确冲突但费用口径不清、必需属性缺失或存在分歧，输出“需要补充信息”。
4. 其余输出“符合已知条件”，不等于证明餐厅实际质量好。

费用测试统一假设为美元且含税及小费；这是假设，不是对原始截图费用的补全。低盐等偏好在真实应用中仍需核对评论对象和主观阈值。本演示消费人工结构化字段，不实现自动抽取或训练模型。

## 比较基线与可复现检查
策略A人为规定好评比例≥60%即通过，不区分用户；策略B按上述约束规范输出三种状态。这是教学基线，不代表小红书当前推荐系统。

运行 `node test-lab.cjs`（在本目录），会检查全部12个夹具及预算边界、同字段输入一致性、未知值处理。英文和中文夹具使用相同人工字段，因此相同输出不能证明跨语言文本理解能力。通过率只说明代码符合已写规范，不代表独立预测准确率，也不是策略B的业务提升。夹具上的A/B差异由测试设计产生，不构成研究发现。

## 下一步真实验证方案
先收集约30–60条有来源和日期的材料，覆盖多家餐厅，并将规则开发材料与后续测试材料分开。若检验跨语言差异，应匹配餐厅、菜品、时间及费用口径；当前没有跨文化效果结论。

请第二位标注者独立标注同一批未见材料，再讨论分歧。记录每个字段的一致率与分歧矩阵；类别分布允许时补充Cohen's kappa，不能通过讨论后的统一标签冒充独立一致性。

邀请6–10位参与者作探索性可用性测试，不用于显著性结论。真正的用户测试中，A应是同等信息量的原文或整篇情绪摘要，不能使用网页中故意简化的60%规则充当有效对照。对不同但相当的任务，交叉平衡A/B摘要的呈现顺序；避免同一人反复看同一材料造成记忆优势。记录关键约束识别时间、理由复述完整度、未获支持的推断数及主观有用性。任务完成更快但遗漏硬约束不能算成功。

实验结束后根据真实记录填表；不预填用户提升数据。若B更慢或增加困惑，则检查字段过多、优先级不清、提示语过长等问题，再修订。

## 面试讲解与简历定位
这是“内容理解与决策支持原型”，不是已上线运营项目。可以描述从真实决策提出问题、制定方面级标注规范、设计12个合成边界场景、实现两种策略比较与可解释输出。不能描述成真实用户增长、标注团队建设或模型上线成果。

English summary: A content-decision prototype with 4 real source excerpts and 12 separately labeled synthetic fixtures. The implemented engine consumes manually structured fields. Regression tests measure specification compliance, not extraction accuracy or user impact. Independent annotation and counterbalanced usability studies remain planned.
